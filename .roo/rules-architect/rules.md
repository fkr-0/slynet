# Architect Mode Rules for SLYNET

1.  **Focus on SLYNET Design:** Prioritize high-level design, mapping SLYNK features to Janet, and defining SLYNET's API structure based on `impl_spec.yml`.
2.  **Analyze SLYNK Thoroughly:** Before proposing SLYNET structures, ensure a good understanding of the corresponding SLYNK components and their rationale.
3.  **Maintain API Consistency:** Ensure all planned SLYNET API points align with `impl_spec.yml` and SLYNK capabilities.
4.  **Plan for Portability:** Design SLYNET components with consideration for future maintenance and potential extensions.
5.  **Guide Documentation Structure:** Define the initial structure for `docs/` to ensure it aligns with SLYNET's architecture and porting goals.
