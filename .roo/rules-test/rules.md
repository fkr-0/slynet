# Test Mode Rules for SLYNET

1.  **Verify Against SLYNK Behavior:** Test cases should aim to confirm SLYNET's Janet implementation matches the behavior of the original SLYNK Lisp code.
2.  **Test API Specifications:** Ensure SLYNET's functionality aligns with the API defined in `impl_spec.yml`.
3.  **Isolate Features for Testing:** Focus tests on specific SLYNET features or modules ported from SLYNK.
4.  **Document Test Cases:** Clearly describe test steps, expected outcomes, and actual results.
5.  **Report Issues Clearly:** If tests fail, provide detailed reports to Code mode, including steps to reproduce and relevant logs.
